# Handoff NSE-004 — Live orders impossible by default

## Summary

SmartAPI `placeOrder`, `modifyOrder`, and `cancelOrder` now run only from `broker/live_guard.py`, and only after `assert_live_orders_allowed()`.

Live is allowed only when all of these are true:

- `LIVE_ORDERS_ENABLED=true`
- `LIVE_ORDERS_CONFIRM=true` (the second confirmation env var)
- `mode=live`
- `live_orders=true`

Both new settings default to false and are unset in `.env.example`. Pytest and `NSE_FORCE_PAPER` force `live_orders`, `live_orders_enabled`, and `live_orders_confirm` back to false, so tests cannot arm a live send.

Paper and shadow (`engine/paper_engine.py`, `engine/book_a_shadow.py`, `PaperBroker`, `OrderManager` on the paper broker) do not call those SDK methods. A mock raises if they do.

Process start logs `mode=<paper|live>` and `live=OFF` unless the guard would pass (`engine/runner.py`).

No broker login and no order was sent.

## Files changed

- `broker/live_guard.py` (added) — the guard and the only SDK order calls
- `broker/angel.py` — place / modify / cancel call the guard first
- `config/settings.py` — `live_orders_enabled` and `live_orders_confirm`, default false, forced off under pytest

- `engine/runner.py` — startup line includes mode and `live=OFF`

## Assumptions

- The second confirmation env var is `LIVE_ORDERS_CONFIRM`. It must be true, same acceptance as other pydantic bools (`true` / `1` / `yes`). It is absent by default.
- The plan A15 pair (`mode=live` and `live_orders=true`) stays required. The new flags do not replace it. Turning on only the new vars does not allow an order.
- `assert_live_orders_allowed()` raises `broker.errors.Rejected`, the existing do-not-retry error.
- This branch was created from `main` (`aae5f1f`). AUD-3 stays on `jarvis/AUD-3`.
- The kill switch is still not inside this guard. AUD-3 recorded that. This ticket did not change it.

## Known gaps

- `core/orders.py` still calls `broker.place_order` with keywords aimed at `PaperBroker`. It does not call SmartAPI. Wiring it to `AngelBroker` would not match the Angel signature, so it still fails before a send.
- Unmerged branches (`fix/c19-review` and its ancestors) have their own copy of `broker/angel.py`. This guard is not on those branches.
- A fully armed process (all four flags true) can still reach the SDK. That path is not exercised by tests, and pytest cannot turn it on.

## Security impact

Default and test runs cannot place, modify, or cancel at the broker. Two extra unset env vars now sit in front of the old dual gate. Paper and shadow do not gain an order client. No secrets were added.
