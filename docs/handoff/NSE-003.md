# NSE-003 — Secrets hygiene

## Summary

Angel SmartAPI key, client code, MPIN and TOTP seed are read in one place: `config/broker_secrets.py`. That function takes them from Settings, which is filled from the environment or, after `apply_db_secrets()`, from the encrypted Postgres store. If any of the four is missing it raises `BrokerSecretsMissing` with the env names only, and `AngelBroker.login` returns before `generateSession`.

Log lines go through a stdlib formatter patch (`config/log_redact.py`), installed on the first `get_settings()` call. The API key and TOTP seed are removed wherever they appear. The MPIN and client code are removed when the log names that field.

`docs/security/secrets-history.md` is a gitleaks scan of the full git history. It records file, commit and secret type only. This scan found nothing, so there is nothing marked ROTATE. History was not rewritten.

NSE-001 was already committed and pushed on `jarvis/nse-001` before this branch. This branch is `jarvis/nse-003`, cut from `main` (lowercase; the ticket said `jarvis/NSE-003`).

## Assumptions

- Fail-fast applies when broker code asks for the credentials. The process still starts in paper mode with no Angel keys. `POST /api/keys/test-angel` still returns `NOT_CONFIGURED` instead of a 500.
- The Postgres key store stays. `secrets_loader` copies it into Settings. Broker code does not read the four fields itself.
- The keys page still reads Settings to mask, compare and reveal. That is the store UI, not a second broker login path.
- A 4-digit MPIN is redacted on `pin=`, `mpin=` and `password=`. It is not stripped out of unrelated numbers such as prices. The API key and TOTP seed (8 characters or more) are stripped wherever they appear.
- The service uses stdlib logging. `structlog` is pinned but unused, so redaction patches `logging.Formatter.format` rather than adding a structlog pipeline.
- The string removed from `tests/test_test_angel.py` was the public pyotp example, not an Angel credential. Tests now use a repeated placeholder.
- The history scan covered this branch, which is `main` plus the NSE-003 commits. It did not include the unmerged `jarvis/nse-001` branch. That branch added tooling only.
- An empty history scan is written as "nothing to rotate" rather than an empty ROTATE table.

## Known gaps

- A short MPIN or client code logged with no field name is not redacted.
- Values can still sit in an exception object until something logs it. Logged text is redacted.
- Admin reveal on `/keys` still returns a saved value to an authenticated admin. That path already existed.
- This branch's GitHub Actions file is still main's ruff + pytest job. gitleaks is not in that workflow. NSE-001 adds it on the other branch.
- TOTP in `login_check` still uses `pyotp.TOTP.now()` (local clock). The UTC fix in plan V0-9 was left alone.

## Security impact

No live-order flag changed. A missing credential no longer reaches Angel. Logs no longer keep the API key, TOTP seed, or a named MPIN or client code. The history report contains no values. No history rewrite.
