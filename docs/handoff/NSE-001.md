# NSE-001 — Dev setup + CI

## Summary

`make setup` installs the pinned requirements into `.venv`. `make check` runs ruff, mypy, the offline pytest suite, and pip-audit. `make ci` adds a blocking gitleaks scan of the working tree.

GitHub Actions runs on every push and every pull request. The job installs the pins, then runs lint, typecheck, tests, pip-audit, and the working-tree secret scan. A second gitleaks step scans git history and is report-only (`continue-on-error: true`). The workflow never calls `scripts/login_check.py` or SmartAPI.

Pytest replaces `SmartApi.SmartConnect` (and the websocket classes) with a fake that raises before any login or order call, and it refuses sockets that are not loopback. `NSE_FORCE_PAPER=1`, `MODE=paper`, and `LIVE_ORDERS=false` are set for the suite and for CI. `DATABASE_URL` is removed from the environment at session start so pytest does not open Postgres.

`.env.example` lists variable names only. Optional secrets are blank. Numbers, bools, modes, and paths stay commented so copying the file cannot override the paper defaults with an empty string.

## Assumptions

- Branch is `jarvis/nse-001`. The ticket asked for `jarvis/NSE-001`; branch names are lowercase.
- `make setup` uses the stdlib venv and pip. The old README used `uv`. Either install path still matches the pinned files. CI uses pip.
- Typecheck is mypy 1.15.0 with `ignore_missing_imports`. Fifteen modules that already fail mypy are listed under `[[tool.mypy.overrides]]` with `ignore_errors` so this ticket does not rewrite trading code. The rest of the tree is checked.
- `.env.example` comments every setting whose empty value would override a default (`MODE`, `LIVE_ORDERS`, sizes, paths). Blank lines are only optional secrets and optional strings.
- pip-audit on the current pins reports advisories in aiohttp 3.11.10, cryptography 44.0.0, pyarrow 18.1.0, python-dotenv 1.0.1, and pytest 8.3.4. This ticket does not upgrade dependencies. Those IDs are in `security/pip-audit-baseline.txt`. A new ID fails `make audit`.
- CI now runs on every branch, not only `main` and `feat/**`. The deploy workflow is unchanged.
- Loopback sockets stay allowed so aiohttp's TestServer still works. `local_ip()` in the SmartConnect header helper gets `OSError` and falls back to `127.0.0.1`.
- History scan is report-only in CI even though this repo's history currently has no findings.

## Known gaps

- The ignored mypy modules are not typechecked: `config.settings`, `data.history`, `engine.state`, `lab.backtest`, `lab.ledger`, `lab.portfolio`, `notify.telegram`, `scripts.run_prereg_trials`, `strategies.gap`, `strategies.registry`, `web.portal_api`, `web.portal_data`, and three tests.
- `config.settings` still defines the opening-tracker fields twice. The values match. Left alone.
- Known dependency advisories above are not patched.
- A leak that exists only in git history does not fail CI.
- `deploy.yml` still runs its own ruff and pytest. It does not run mypy, pip-audit, or gitleaks. Pytest there does use the new offline guard.
- The gitleaks installer supports linux and mac only.

## Security impact

No live-order path was added or enabled. `mode` still defaults to paper and `live_orders` still defaults to false. CI sets both guards and never calls the broker.

Tests cannot construct a real SmartAPI session or open a public socket. The working-tree secret scan blocks a new committed secret. `.env.example` has no values.

The audit baseline does not hide future advisories. It does mean the pre-existing advisories on the pinned packages do not fail this CI job.

## Rollback

This branch only changes developer tooling, CI, tests, and docs. There is no migration and no deploy.

```bash
git checkout main
git branch -D jarvis/nse-001
git push origin --delete jarvis/nse-001
```

Deleting the remote branch is the owner's choice. Reverting the merge commit on main is enough if the branch was already merged.
