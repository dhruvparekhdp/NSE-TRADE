# Handoff NSE-006 — Paper and shadow scheduled jobs

## Summary

The four stubbed runners now do local work in paper and shadow. They do not call SmartAPI `placeOrder`, `modifyOrder`, or `cancelOrder`.

- Market data refresh stores the quotes it is given (the runner passes the on-disk cache). It does not download Yahoo or the scrip master.
- Signal generation records signals while the cash session is open. Shadow writes the signal only. Paper book A also opens one virtual share in SQLite.
- MIS square-off closes open paper book A at a clock that must be before 15:30 IST. The default is `settings.square_off_at` (`14:55`). CNC (book B) stays open.
- The end-of-day snapshot writes absolute paper P&L for the day. A second run stores the same numbers.

Each job calls `live_orders_allowed()` in `broker/live_guard.py` before it writes. `assert_live_orders_allowed()` raises when live is off, so paper work does not call it unless the guard already says live is armed. Even then the job only writes SQLite.

Holidays, weekends, and a year with no holiday file are skipped. A re-run does not insert a second quote row, signal, trade, or snapshot for the same key, and it does not book MIS P&L twice.

No broker login and no order was sent.

## Assumptions

- `assert_live_orders_allowed()` cannot be the first call of a paper job, because it raises while live is off and these jobs must still run. They call `live_orders_allowed()` instead, and they call `assert_live_orders_allowed()` only when that returns true. They still never call an order method.
- MIS square-off must be strictly before 15:30 IST. `15:30` raises `ValueError` and leaves positions open. The scheduler falls back to `14:55` if the setting is that late, so the process still starts.
- A special session uses its own `square_off_at` (Muhurat 2026-11-08 is 15:10), which is still before 15:30. New signals stay off on that day unless `trade_special_sessions` is true.
- The regular performance snapshot waits until 15:40 IST, after the 15:30 cash close and after the 2026 closing auction that ends at 15:35. A special session snapshots at or after its own close.
- Market refresh is allowed at any time on a trading day, including the 08:30 IST cron before the open. It does not run on a holiday or weekend. New signals run only in `OPEN`.
- The paper book records one virtual share per signal so a re-run cannot stack size. It does not call the risk sizer. Book B is recorded as a shadow signal and is not opened or squared off here.
- New quote and snapshot prices are decimal strings. The existing `trades` table stays `REAL`, matching migration 001. Costs use `core.costs.round_trip` once, when the MIS row first closes.
- This environment allowed a new branch `jarvis/NSE-006` from `main`.

## Known gaps

- Login, websocket start/stop, no-new-entries, backfill, and backup are still log-only stubs.
- `job_free_quotes` can still call Yahoo. `job_news` still does not fetch RSS. Neither was one of the four jobs in this ticket.
- The kill switch is still outside the live-order guard.
- Unmerged `fix/c19-review` has its own `broker/angel.py`. This work does not update it.
- NSE-004 is not on `main`. Merging both pull requests will overlap on the guard files. If NSE-004 merges first, rebase this branch onto `main` and drop `52b4e58`.
- A process with every live flag on still cannot send from these jobs, but the guard module itself can still reach the SDK if something else calls it. Pytest cannot turn those flags on.

## Security impact

These jobs do not enable live orders and do not call broker order methods. Paper and shadow write the local SQLite file only. No secrets were added. The default mode stays `paper` and `live_orders` stays false.

## Rollback

Do not merge the pull request. To drop the branch after it is unused:

```bash
git checkout main
git branch -D jarvis/NSE-006
git push origin --delete jarvis/NSE-006
```
